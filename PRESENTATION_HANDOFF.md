## Project Identity

Project name: ATIS, also described in the repo as Drive IQ / ATIS.

Full idea: Automated Tyre Inspection System for highway or checkpoint
operations, especially aligned with an NHA-style operator dashboard.

Core purpose: reduce manual tyre inspection friction by letting an operator
upload or capture tyre images, run AI classification, store the inspection,
flag risky results, and manage follow-up through alerts and reports.

Main stack:
- Python Flask web application
- SQLAlchemy database models
- Alembic / Flask-Migrate migrations
- Ultralytics YOLOv11 classification model
- OpenCV image-processing support

## One-Sentence Product Summary

ATIS is an AI-assisted tyre safety inspection platform that classifies uploaded
or camera-captured tyre images as safe or unsafe, records inspection evidence,
raises alerts for unsafe cases, supports human review, and exports operational
reports and corrected data for future model improvement.

## Problem Being Solved

Manual tyre inspection at checkpoints is slow, inconsistent, and hard to audit.
Operators need a repeatable way to record inspections, preserve image evidence,
identify cracked tyres quickly, and escalate unsafe cases. Supervisors need
visibility into trends, alerts, and review outcomes. A deployment needs security,
roles, auditability, and clear limits around model confidence.

## Solution Overview

ATIS provides:
- Image upload inspection through a browser dashboard.
- Browser-camera live analysis route for sampled frames.
- Standalone OpenCV live-camera runner for fixed toll-booth scan zones.
- AI classification of tyre images as `normal` or `cracked`.
- Fail-safe decision policy: only confident `normal` predictions are marked
  `safe`; cracked or low-confidence normal predictions are treated as unsafe /
  manual review.
- Automatic alert creation for unsafe tyre predictions.
- Inspection history with filters, duplicate image detection, saved filters, and
  image evidence.
- Human review workflow with correction labels.
- Reports with charts plus PDF, CSV, and model-feedback exports.
- Role-based access for Admin, Supervisor, Operator, and Inspector users.
- Audit logging for inspection, user, alert, report, and workflow actions.
- Production configuration with strong secret enforcement, secure cookies,
  rate limiting, Docker, migrations, and optional S3 image storage.

## What The Current AI Actually Does

Current shipped model:
- Task: image classification.
- Classes: `normal`, `cracked`.
- Base model: `yolo11n-cls.pt`.
- Framework: Ultralytics YOLO classification.
- Input size recorded in model card: 224.
- Runtime weights path:
  `runs/classify/runs/classify/ATIS_Project/tyre_safety_model/weights/best.pt`.

Inference policy:
- `normal` with confidence >= `ATIS_CONF_THRESHOLD` is `safe`.
- `normal` below threshold is `unsafe` and should be reviewed manually.
- `cracked`, `crack`, or `cracking` is `unsafe` at any confidence.
- Unknown classes are treated as unsafe/manual review.
- Default confidence threshold is `0.60`.
- This is intentionally asymmetric and fail-safe: the system is stricter about
  passing a tyre as safe than it is about flagging one for review.

Crack visual boxes:
- The UI can display crack marker boxes.
- These are generated by an OpenCV black-hat morphology heuristic.
- They are meant as visual aids to point near likely crack regions.
- They are not trained detector boxes and should not be presented as object
  detection performance.

Non-tyre gate:
- The classifier includes a best-effort rejection path for obvious non-tyre or
  blank/flat frames.
- It checks image contrast and edge density.
- It can also use an optional COCO-style object model (`yolo26n.pt`) to reject
  obvious non-tyre objects.
- This is best-effort, not a certified tyre detector.

## Model Metrics To Mention Carefully

From the committed model card and calibration docs:
- Held-out test evaluation date: 2026-07-04.
- Test split: 152 cracked images and 146 normal images.
- Test top-1 accuracy: about 99.0%.
- Cracked recall: about 99.3%.
- Normal recall: about 98.6%.
- Missed-defect rate on curated test split: about 0.7%.
- Good-tyre false-flag rate on curated test split: about 1.4%.
- Validation/training record: best top-1 validation accuracy around 99.2% at
  epoch 95.

Required caveat:
These are curated dataset metrics, largely from controlled or web imagery. They
are good for a demo and validation of the pipeline, but field validation is still
needed on real checkpoint cameras, day/night lighting, wet/dirty tyres, motion
blur, shadows, glare, and partial tyre frames.

## Dataset And Training Pipeline

Dataset layout:
- `ATIS_Dataset/{train,val,test}/{normal,cracked}/`
- Ultralytics classification layout.

Current dataset state recorded in `DATA_HANDOFF.md`:
- Total images: 1,973.
- Train: 1,380 images.
- Validation: 295 images.
- Test: 298 images.
- Train split: 705 cracked, 675 normal.
- Validation split: 151 cracked, 144 normal.
- Test split: 152 cracked, 146 normal.

Dataset sources recorded:
- Local `Tire Textures/`, which corresponds to Kaggle
  `jehanbhathena/tire-texture-image-recognition`.
- A likely second Kaggle source:
  `warcoder/tyre-quality-classification`, already merged and SHA-1 renamed.

Dataset preparation script:
- `prepare_dataset.py`.
- Pools images from one or more sources.
- Maps source folder names into the two classes `normal` and `cracked`.
- Drops corrupt files.
- Removes exact duplicate images by SHA-1.
- Optionally removes near-duplicates using perceptual hashing if `imagehash` is
  installed.
- Creates a stratified 70/15/15 train/validation/test split.
- Uses content-hash filenames to reduce leakage risk.

Training and evaluation scripts:
- `train_model.py`: trains the YOLO classifier.
- `colab_train.ipynb`: GPU training route for Colab.
- `evaluate_model.py`: validates classifier metrics and threshold behavior.
- `test_tyre.py`: single-image CLI inference test.
- `atis_inference.py`: shared inference helper used by web and live workflows.

Future detector path:
- `train_detector.py` exists as a scaffold for a real YOLO object detector.
- It expects a bounding-box detection dataset with `data.yaml` and YOLO labels.
- It is not the current production/demo inference path.
- A switch to detector should only be claimed after detector data, weights, and
  per-class metrics such as precision, recall, and mAP are available.

## Main Application Workflow

1. User logs in.
2. Operator opens the inspection form or live camera page.
3. Operator uploads/captures a tyre image.
4. The app validates the image type and size.
5. If plate text is not manually entered, optional OCR tries to read the plate.
6. The YOLO classifier predicts `normal` or `cracked`.
7. The fail-safe threshold maps the prediction to `safe` or `unsafe`.
8. The app stores an inspection row with metadata, image evidence, confidence,
   model path/version, threshold, inference time, plate source, and defects.
9. If unsafe and not a non-tyre rejection, an alert is created automatically.
10. Supervisors/admins can acknowledge, route, comment on, and resolve alerts.
11. Reviewers can approve/reject/label inspections and add corrections.
12. Reports and model-feedback exports can be generated from stored data.

## Live Camera Features

Browser live page:
- Route: `/live`.
- Uses browser camera access through `getUserMedia`.
- Sends sampled frames to `/api/live/analyze`.
- Analysis is read-only by default.
- "Capture and log" style flow can persist a selected frame through the normal
  inspection route.
- Live frame analysis is rate limited.

OpenCV fixed-camera runner:
- Script: `live_video_inspection.py`.
- Uses calibrated tyre scan zones.
- Script: `calibrate_live_zones.py` lets a user draw zones and save
  `config/live_zones.json`.
- Each zone is cropped and analyzed when motion is detected.
- Requires repeated unsafe predictions before logging, reducing noisy one-off
  alerts.
- Supports cooldown between logs per zone.
- Can run display-only with `--no-db-log`.

## Important Boundaries And Honest Claims

Allowed claims:
- ATIS performs binary tyre image classification: `normal` vs `cracked`.
- ATIS uses a fail-safe threshold so only confident normal predictions pass.
- ATIS stores inspection evidence and metadata.
- ATIS creates alerts for unsafe tyre predictions.
- ATIS supports operator workflows, human review, audit logging, and reporting.
- ATIS can export corrected data for model improvement.
- ATIS has local/demo and production-oriented deployment paths.

Do not claim yet:
- Certified production-grade tyre safety enforcement.
- Reliable night/low-light operation without controlled lighting or new field
  evaluation.
- Trained object detection or measured bounding-box localization accuracy.
- Bulge, puncture, flat spot, tread depth, or inflation detection.
- General vehicle or tyre detection certification.
- Perfect OCR accuracy.

Best limitation wording:
"The current model is suitable for a controlled project demo and shows strong
curated test performance, but real checkpoint deployment requires field
validation on the target cameras and conditions."
